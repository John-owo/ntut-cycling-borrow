# Reservation lifecycle contract (2026-10-08)

Keep legacy queue and its data intact. New independent numbered assets must be physically reconciled by officers before activation; never auto-convert aggregate opening loans into available assets. An approved member receives a 256-bit token, only its SHA-256 stored. Staff verifies identity/eligibility and sets expiry. No guessed credentials or self-approved membership.

Transport: `POST /api/lifecycle` body `{action,token?,payload:{}}`; cloud `public.lifecycle(p_action text,p_token text,p_payload jsonb)`. Staff `POST /api/admin/lifecycle` body `{action,payload:{}}`; cloud `public.lifecycle_admin(p_action text,p_payload jsonb)` enforces existing require_admin/MFA/session. Frontend adapters in public/api.js owned by parent. JSON uses camelCase in both adapters. Errors use existing HTTP mechanism. All mutating actions transactional; replay requestId checks exact payload. All private tables inaccessible to anon/authenticated directly. Read actions never return another member's PII.

Common data:
- asset `{id: UUID,code,name,kind:'bike'|'accessory',state:'available'|'inspection'|'maintenance'|'retired'}`. Asset state is physical availability; booked and in-use computed from reservations. Upsert assets with staff action `asset` payload `{id?,code,name,kind,state,reason}`. Do not allow making a currently in-use/inspection asset available to bypass return/review.
- member staff action `member` payload `{id?,studentId,name,contact,validUntil:ISO,active:boolean,token?:64hex,reason}`; new requires token generated clientside; updates must not rotate token implicitly. Output `{member}` safe projection. Token never returned or logged. Staff issues/shares token manually with member.
- policy staff action `settings` payload `{location,instructions,terms}`; require all nonempty before reservations; server hashes terms and returns version. No invented official location/terms. Initial terms may reuse existing published borrow rules. Policy snapshot must accompany signature.
- calendar member/public action `calendar` payload `{start:ISO,end:ISO}` range <=42 days, returns `{assets,bookings:[{id,assetIds,start,end,status}],settings:{location,instructions,terms,termsVersion},updatedAt}`. Public contains no member id/name/contact/signature. Active overdue/in-use reservation blocks new reservations even after end until returned. Calendar includes those blocking records outside window.
- member `me` returns `{member,reservations:[reservation],settings}`. Reservation `{id,memberId,assetIds,start,end,status:'reserved'|'in_use'|'returned'|'inspection'|'cancelled',createdAt,pickedUpAt,returnedAt,inspections:[{phase:'pickup'|'return',checks,notes,abnormal,createdAt}],photos:[{id,reservationId,assetId,phase,slot,mime,size,sha256,uploadedAt}],signature:{name,terms,termsVersion,signedAt,image?}|null}`. No photo base64 in bulk reads. Staff list action `list` returns `{assets,members,reservations,settings,events,notifications}`; notification is persistent in-app abnormal event requiring officer attention.
- member `reserve` payload `{requestId:UUID,assetIds:UUID[],start:ISO,end:ISO}` includes exactly one bike and optional accessories, unique IDs; start >= now, end>start, max duration 5 days. Expiry >= end. Check active membership, asset readiness, legacy active same student, any existing active member reservation. Serialize shared assets and member; half-open intervals [start,end); no overlap including accessory; atomic insert. Response `{reservation}`. Idempotency scoped to member and exact request payload, including retries after terminal status.
- member `photo` payload `{requestId,reservationId,assetId,phase,slot:'left'|'right'|'drivetrain'|'damage',mime:'image/jpeg'|'image/png'|'image/webp',data:base64}`. max decoded 8 MiB; validate magic bytes, sha256, bind own reservation and assigned BIKE; pickup only reserved and in pickup window; return only in_use. Insert-only append histories; never replace/delete original. All four slots required even no damage (damage detail documents existing condition). Response `{photo:metadata}`. File data only via member `photo_read` payload `{id}`; staff `photo_read` same; `{photo:{...metadata,data}}`. Private DB binary storage is deliberate for serverless Pages compatibility; upload one photo per request, size limits visible.
- member `pickup` payload `{requestId,reservationId,checks:{frame:true,tires:true,brakes:true,gears:true,accessories:true},notes:string,signature:{name,accepted:true,termsVersion,image:dataURLPNG}}`. Require all bools true, four pickup photos, matching current termsVersion and name, signature PNG <=256 KiB, nontrivial drawing (UI); pickup allowed only start<=now<end. Enforce eligibility and no concurrent in_use bike (overdue). Transaction inserts inspection and immutable signature snapshot then changes reserved->in_use actual timestamp. No staff shortcut bypass.
- member `return` payload `{requestId,reservationId,checks:{frame:boolean,tires:boolean,brakes:boolean,gears:boolean,accessories:boolean},notes:string,abnormal:boolean}`. All keys must be booleans; four return photos; any false check forces abnormal. Normal ->returned, abnormal ->inspection and ALL assets inspection; persistent staff notification/event. Store actual time, never overwrite pickup info. Expired/revoked member may still return/read own record.
- member `cancel` payload `{requestId,reservationId,reason}` only reserved; no mutation of in_use.
- staff `resolve` payload `{requestId,reservationId,reason,state:'available'|'maintenance'}` only inspection; marks reservation returned and assigned assets chosen state, audit/notification resolved. Staff `cancel` same only reserved, with reason. Staff `asset` must reject changing reserved/in_use assets away from available without cancelling reservation (inspection/maintenance edits must not invalidate bookings silently). Staff membership revocation blocks new reservation/pickup, never return/read.
- Staff `export` returns full lifecycle backup including photos/base64, signatures, receipts, events, membership token hashes (never raw token). Exports private; append audit. Legacy export will include lifecycle via integration if practical.

Tests: actual HTTP/disk SQLite + PostgreSQL/PGlite all migrations, private grants, ownership, invalid phases/missing photos/checks/signature/eligibility, overlap bike/accessory, adjacent intervals, retry mismatch, abnormal quarantine/officer resolve, persistent originals, legacy regressions. PGlite tests do not claim real multi-connection cloud concurrency.

Capacity: private original-photo budget 192 MiB, max photo 8 MiB. Staff list includes `storage:{usedBytes,reservedBytes,budgetBytes,maxPhotoBytes}`. Reserve admission allocates 64 MiB for 8 mandatory slots. All original history remains counted; each distinct completed slot releases its 8 MiB reservation while counting actual bytes. Extra photos cannot consume other borrowers' mandatory return allocation. Cancel/terminal return releases unused slots. Provider database size and non-photo growth still require monitoring; this is not unlimited object storage.
